# Events

<LastReviewed date={metadata.lastReviewed} />

The API exposes a compact event stream for clients that need to react to state changes without polling the full asset list. The payload is a JSON array ordered newest-first.

<ApiEndpoint method="GET" path="/v1/events" description="Most recent contract events captured by the indexer.">

```bash
curl "$API_BASE_URL/v1/events?limit=20"
```

```json
[
  {
    "id": 42,
    "contract": "CDL...",
    "event_type": "Transfer",
    "ledger": 3514152,
    "timestamp": "2026-07-09T08:43:12.101772791+00:00",
    "data": {
      "from": "GA...",
      "to": "GB...",
      "amount": "100"
    }
  }
]
```

</ApiEndpoint>

**Response schema** (`Event`, per event):

| Field | Type | Unit | Nullable | Description |
|-------|------|------|----------|-------------|
| `id` | integer | Event id | No | Indexer-assigned event id |
| `contract` | string | — | No | Contract address that emitted the event |
| `event_type` | string | — | No | Event name |
| `ledger` | integer | Ledger sequence | No | Ledger containing the event |
| `timestamp` | string | RFC 3339 timestamp | Yes | JSON `null` when the ledger timestamp is unavailable |
| `data` | JSON value | — | No | Raw event payload |

Each event includes the contract address, event name, ledger, timestamp (when available), and the raw payload emitted by the contract.

**Response schema:**

| Field | Type | Description |
|---|---|---|
| `id` | number | Sequential event ID |
| `contract` | string | Address of the contract emitting the event |
| `event_type` | string | Event name (e.g. `Transfer`, `Mint`, `Burn`, `Valuation`, `created`, `claim`) |
| `ledger` | number | Ledger sequence number where the event was recorded |
| `timestamp` | string or null | ISO 8601 timestamp of ledger close |
| `data` | object | Event-specific data payload |

**Pagination:**

The events endpoint is cursor-paginated. Pass `limit` (default `20`, max `100`) to bound the page size and `cursor` to fetch the next page. The response is a JSON array; when more events are available the `Link` header carries a `rel="next"` URL whose `cursor` query parameter can be replayed verbatim.

```bash
# First page
curl -i "$API_BASE_URL/v1/events?limit=20"
# Follow the Link: <...?cursor=...>; rel="next" header for the next page
curl "$API_BASE_URL/v1/events?limit=20&cursor=$CURSOR"
```

**Event payload amount units:**

Amounts inside `data` depend on the contract and event type, in accordance with the contracts specification:

| Event type | Amount field | Unit / Base | Conversion |
|---|---|---|---|
| `Transfer`, `Mint`, `Burn` | `data.amount` | Asset token base units (`i128` string) | `Number(BigInt(data.amount)) / 10 ** token.decimals` |
| `Valuation` | `data.new_valuation` | USD cents (`i128` string) | `Number(BigInt(data.new_valuation)) / 100` |
| Dividend `created` | `data.total_amount` | Payment token base units (`i128` string) | `Number(BigInt(data.total_amount)) / 10 ** payment_token.decimals` |
| Dividend `claim` | `data.amount` | Payment token base units (`i128` string) | `Number(BigInt(data.amount)) / 10 ** payment_token.decimals` |

<CalloutBox variant="tip" title="Event amount conversion example">
```typescript
// For a Transfer event with amount = "100" and token decimals = 2:
const rawAmount = BigInt(event.data.amount);
const displayAmount = Number(rawAmount) / (10 ** 2);
// => 1.00 token
```
</CalloutBox>

**Event types by entry point:**

The indexer records one event per state-changing contract entry point. The table below maps the current contract surface to the `event_type` values you will see on this endpoint.

| Entry point | `event_type` | Notes |
|---|---|---|
| `transfer`, `transfer_from` | `Transfer` | SEP-41 token transfer; `data.amount` in asset base units |
| `mint` | `Mint` | SEP-41 issuance; `data.amount` in asset base units |
| `burn`, `burn_from` | `Burn` | SEP-41 redemption; `data.amount` in asset base units |
| `approve`, `allowance` | `Approve` | SEP-41 allowance update; `data.amount` in asset base units |
| `batch_transfer`, `batch_mint`, `batch_burn` | `Transfer`, `Mint`, `Burn` | One event per item in the batch, sharing the same `ledger` |
| `set_valuation` | `Valuation` | `data.new_valuation` in USD cents |
| `set_min_holding_period` | `MinHoldingPeriodUpdated` | `data.min_holding_period` in seconds |
| `transfer_admin`, `accept_admin`, `renounce_admin` | `AdminTransferInitiated`, `AdminTransferred`, `AdminRenounced` | Two-step admin handover |
| `create_dividend` | `created` | `data.total_amount` in payment token base units |
| `claim_dividend` | `claim` | `data.amount` in payment token base units |
| `set_dividend_deadline` | `DividendDeadlineUpdated` | `data.deadline` is a ledger sequence |
| `reclaim_dividend` | `DividendReclaimed` | `data.amount` in payment token base units |
| `cancel_dividend` | `DividendCancelled` | `data.dividend_id` identifies the cancelled dividend |

<CalloutBox variant="note" title="Batch operations">
Batch entry points emit one event per item rather than a single aggregate event. Filter by `event_type` and group by `ledger` to reconstruct a batch.
</CalloutBox>
